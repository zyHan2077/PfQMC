## 防止“算出来必正”的对照

允许族之外的无约束实跃迁负权重对照，在固定种子 731 的第 0 个配置即给出

```text
Fock      = -1860.205695870663
Pfaffian  = -1860.205695868800 + 2.1962e-12 i
phase     = -1 + 1.1806e-15 i
```

因此实现能够保留实际负号，没有从行列式正平方根构造“无符号”结论。
在 `Q(0.2,-0.15,0.4,0.3)` 中删去所有改变粒子数的矩阵元，
`Tr exp(Q)` 改变约 **1.10736**，确认配对确实参与权重。

## 原模型主程序运行

开始在沙箱内调用主程序时，Intel MPI 报 `OFI endpoint open failed`。
在获得执行许可后于沙箱外运行，四个入口均完成且退出码为 0，未出现 NaN 或 Inf。
这是 MPI 通信环境限制，不能归因于物理模型或 Pfaffian 计算失败。

```bash
source /opt/intel/oneapi/setvars.sh
mkdir -p build/smoke
build/main --MRhoneycomb 2 2 4 0.1 0.7 1 42 10 build/smoke/
build/main --chain 4 4 0.1 0.7 0.3 1 42 10 build/smoke/ 0.2 0 1
build/main --square
build/main --honeycomb
```

实际运行结果：

| 入口 | 设置与结果 |
|---|---|
| `--MRhoneycomb` | `2×2,Ltau=4,dt=0.1,V=0.7`；200 次热化、10 次测量；平均 MR sign=`1+2.0394e-14 i` |
| `--chain` | `L=4,Ltau=4,dt=0.1,V=0.7,delta=0.3,mu=0.2`，开边界、HS scheme 0；1000 次热化、10 次测量；平均 sign=`1+1.6803e-14 i`，能量 `-0.897325` |
| `--square` | 默认 `4×4,Ltau=200,dt=0.1,V=0.7,delta=0.5`；200 次热化、1000 次测量全部完成，退出码 0，耗时 339.142 秒；最后一次定期输出（iter=990）的平均 sign 约 `0.683148`，能量约 `-16.3688` |
| `--honeycomb` | 默认 `4×4,Ltau=100,dt=0.1,V=0.7`；200 次热化、1000 次测量全部完成，退出码 0，耗时 437.945 秒；最后一次定期输出（iter=990）能量约 `-28.0626`，未触发代码中的符号偏离报警 |

日志：[MR 蜂窝](logs/honeycomb-MR.log)、[Kitaev 链](logs/chain.log)、[方格](logs/square.log)、[完整蜂窝](logs/honeycomb-full.log)。
以上均为单 MPI 进程运行；没有据此保证多节点通信或任意输入参数均正常。

检查源码时发现：`main_square()` 的 `rawSign` 初始化为 1，实际重算行已被注释，
所以输出 `raw sign ave=(1,0)` 是占位数值，不能用来验证增量符号。
方格默认参数含配对 `delta=0.5`，运行中出现正负符号波动，本次没有证明该模型无符号。
另外 CLI 对缺失位置参数没有完整检查，长输出路径使用固定长度字符数组；以上调用使用完整参数和短路径。
这些既有入口问题记录于此，没有在此次四模验证中修改原物理算法或入口行为。

## 结论与适用范围
